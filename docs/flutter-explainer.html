Menjalankan aplikasi

backend Go berjalan lokal di laptop, Flutter tersambung ke sana

Flutter hanya tampilan. Tanpa backend Go yang hidup, login akan gagal dengan pesan "Tidak bisa terhubung ke server".

  1. Pakai Docker (paling mudah)

    cd "I:\Fullstack Web Developer and Flutter Developer\rombong-api"
docker compose up --build -d

  2. Atau tanpa Docker

    go run ./cmd/api

    Butuh PostgreSQL lokal dan file .env; langkah lengkapnya ada di panduan visual backend.

  3. Pastikan hidup

    curl.exe http://localhost:8080/health

    Akun admin bawaan: admin@example.com / Admin12345.

  1. Buat folder platform (sekali saja)

    cd "I:\Fullstack Web Developer and Flutter Developer\rombong-app"
flutter create --org com.aulansah --project-name rombong .

    Ini membuat folder android/, ios/, web/, windows/. File yang sudah ada (lib/, test/, pubspec.yaml) tidak ditimpa.

  2. Install package

    flutter --version   # app ini butuh Flutter 3.35+ (Dart 3.9+)
flutter pub get

  3. Jalankan sesuai target

    TargetPerintahURL backend yang dipakai
    Emulator Androidflutter run10.0.2.2:8080
    Chromeflutter run -d chrome --web-port 3000localhost:8080
    Windows desktopflutter run -d windowslocalhost:8080
    HP asli (Wi-Fi sama)flutter run --dart-define=API_BASE_URL=http://IP-LAPTOP:8080/api/v1IP laptop, cek dengan ipconfig

    Chrome harus port 3000 karena backend hanya mengizinkan origin http://localhost:3000 (CORS).

  1. Analisis statis

    flutter analyze

    Harus "No issues found". Kalau ada error, kirim hasilnya ke Claude.

  2. Unit & widget test

    flutter test

    Tidak butuh backend: semuanya memakai mock, provider override, dan fake backend.

  3. CI di GitHub

    Setelah di-push ke GitHub, workflow .github/workflows/flutter-ci.yml otomatis menjalankan analyze dan test. Hasilnya terlihat di tab Actions repo.

  4. Coba di aplikasi

    1. Login dengan akun admin → masuk ke home, terlihat badge "Admin".
    2. Logout → daftar akun baru dengan password lemah → muncul error validasi.
    3. Daftar dengan email yang sama dua kali → muncul "Email is already registered" dari backend.
    4. Tutup aplikasi lalu buka lagi → langsung ke home (sesi dipulihkan).
    5. Matikan backend lalu buka aplikasi → kembali ke login, dan saat login muncul pesan "Tidak bisa terhubung ke server".

  5. Uji auto refresh lebih cepat

    Access token default berlaku 15 menit. Untuk mencobanya, tambahkan JWT_ACCESS_TTL: 1m di bagian environment service api pada docker-compose.yml, lalu docker compose up -d. Setelah 1 menit, aplikasi tetap jalan tanpa diminta login lagi.

GejalaPenyebab & solusi
"Tidak bisa terhubung ke server"Backend belum jalan, atau URL salah untuk target (lihat tabel di tab 2). HP asli: izinkan port 8080 di Windows Firewall.
Chrome: error CORSJalankan dengan --web-port 3000.
Android: "Cleartext HTTP traffic not permitted"Tambahkan android:usesCleartextTraffic="true" di tag <application> pada android/app/src/debug/AndroidManifest.xml.
Build Android: minSdk dari flutter_secure_storageSet minSdk = 23 atau lebih di android/app/build.gradle(.kts).
pub get: "requires SDK version >=3.9.0"Flutter terlalu lama (butuh 3.35+). Jalankan flutter upgrade.
pub get konflik versiKirim hasil flutter --version; rentang versi di pubspec disesuaikan.

Latar belakang aplikasi

Ini aplikasi toko online yang memakai backend rombong-api. Semua aturan (harga, stok, status pesanan) tetap di server; aplikasi hanya menampilkan dan mengirim aksi user.

Sebagai portfolio, pasangan backend Go + aplikasi Flutter menunjukkan kemampuan end-to-end: merancang API sekaligus memakainya dengan benar, termasuk hal yang sering terlewat seperti refresh token paralel, error validasi per field, dan sesi yang kedaluwarsa.

Alasan memakai Clean Architecture

Semua di widget

  • Widget memanggil HTTP, parsing JSON, dan menyimpan token sendiri.
  • Logika tidak bisa di-test tanpa menjalankan UI.
  • API berubah sedikit → banyak layar ikut diubah.
  • Cepat di awal, makin lambat saat fitur bertambah.

Clean Architecture

  • Domain berisi aturan bisnis, tanpa Flutter dan Dio.
  • Data mengurus HTTP dan penyimpanan.
  • Presentation hanya UI dan state.
  • Tiap layer di-test terpisah dengan objek palsu lewat provider override. Konsepnya sejajar dengan handler–service–repository di backend Go.
